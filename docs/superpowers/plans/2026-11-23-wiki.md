# Wiki Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A wiki module where team members write Markdown pages, file them in a tree of categories, and every page change lands in the existing audit trail.

**Architecture:** Two tables (`wiki_categories` as an adjacency list, `wiki_pages`) with Laravel models, policies and resource controllers, following the protocol module. The protocol Markdown renderer, preview endpoint and editor are first extracted into neutral shared parts, which protocols and wiki both use. Inertia + Vue 3 + PrimeVue pages render the overview tree, page view and editor.

**Tech Stack:** Laravel 12 (PHP 8.5), owen-it/laravel-auditing, Inertia v2, Vue 3 + TypeScript, PrimeVue, Tailwind, PHPUnit, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-23-wiki-design.md`

## Global Constraints

- PHP commands run with `/opt/homebrew/opt/php@8.5/bin/php` (the default `php` is 8.4 and fails Composer's platform check). Below, `PHP` means that binary.
- Work on a branch `feature/wiki` off `develop`.
- Commit messages: `feat: <one sentence>` (or `refactor:`/`test:`), **no** Co-Authored-By trailer.
- Every new UI string goes into `lang/de.json`, German with informal "du", keys in English, alphabetically sorted like the existing file.
- Access: every member of the shared team (`$user->belongsToSharedTeam()`) may view, create and edit pages and categories. A page may be deleted by its creator (`created_by`) or `$user->isSuperAdmin()`.
- Pages live at `/wiki/{slug}`; the slug is generated from the title (`Str::slug($title, '-', 'de')`) **only on create**, a counter `-2`, `-3`… on collision; `create` is reserved. Renaming never changes the slug.
- Categories are not audited. Pages are audited with `$auditDiffed = ['text']`, `$auditExclude = ['edited_by', 'slug']`.
- Credentials are out of scope; nothing in the code stores or handles them.
- Not in scope: public sharing, view rights, download, manual tree ordering, protocol backlinks.

## Review Focus

1. Deleting a category that has no pages but has subcategories → refused, nothing deleted. (Task 3)
2. Moving a category under its own grandchild (not only its direct child) → refused. (Task 3)
3. A title with no sluggable characters (`"???"`, `"🙂"`) → slug falls back to `seite`, not an empty slug or a 404 URL. (Task 4)
4. A page moved to a category that is later renamed or deleted → the old history entry still shows the category path as it was. (Task 4)
5. Two sibling categories named `Finanzen` and `finanzen` at the top level (where `parent_id` is NULL) → second is refused; the same name under different parents is allowed. (Task 3)
